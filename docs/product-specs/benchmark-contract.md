# Benchmark 产品契约

本文定义 InferBench 对用户可见且不应无意漂移的行为。实现和 UI 变化如果修改这些规则，必须在同一 PR 更新本文与测试。

## 支持范围

- 目标协议：OpenAI-compatible `/v1/chat/completions` SSE 流式响应。
- 框架标签：vLLM、SGLang、OpenAI-compatible。
- 目标服务可位于本机、局域网或云端。
- 控制面、实验配置和原始样本保存在本地 SQLite。

## 默认实验

- 并发矩阵：`1, 2, 4, 8`。
- 每档至少运行 3 个独立 repetition。
- 每轮默认 128 个请求。
- 默认 `max_tokens`：128。
- 不同 run 串行执行，避免档位间资源竞争污染结果。
- 完整矩阵进入终态后自动生成本地报告快照，不依赖外部 API。

## 指标语义

- TTFT：请求发出到首个非空文本 chunk。
- Latency：请求发出到响应流结束。
- TPOT：首 token 后每个输出 token 的平均时间。
- Output TPS：成功输出 token 总数除以整轮 wall time。
- Token 速度曲线：按请求解码区间估算的客户端时间序列，不冒充服务端逐 token 遥测。
- 重复轮次对吞吐、延迟和成功率分别求算术平均，并显示 CV 稳定性。

Token 数优先使用服务返回的 usage；缺失时允许估算，但必须保留来源标记。

## 生命周期

- run 状态包含 queued、running、completed、failed、cancelled。
- “停止本轮”取消该 run 的排队或活动工作。
- “停止整组”取消同一 suite 的排队与活动 run。
- 取消已开始的请求时应中断流式读取；已完成样本继续保留。
- 进程异常退出后，遗留的 queued/running run 在下次启动时收口。

## 数据与凭据

- API Key 仅在当前任务内存中使用，不写 SQLite，不出现在历史 API 和日志中。
- 导出数据可以包含实验配置、汇总和样本，但不得包含 API Key。
- 删除操作只允许作用于已结束实验；运行中和排队实验受到保护。

## 对比约束

比较结果只在模型、硬件、prompt 集、采样参数和服务配置可比时有意义。综合评分用于同组排序，不作为跨环境的绝对性能结论。

## 性能报告

- 报告事实只来源于 SQLite 中的 run 与 sample；包含分析版本、生成时间和 run IDs。
- 默认按成功率、相邻档吞吐增益、P95 延迟增长和三轮 CV 给出饱和点、推荐并发与证据等级。
- 未配置用户 SLO 时，推荐必须标明为“默认平衡规则”，不得声称生产最优。
- 报告允许补充成功率/吞吐/延迟 SLO 和环境说明，保存时使用同一批原始样本重新分析。
- 报告不得包含 API Key、完整 prompt 和响应正文。
- 支持 JSON、独立 HTML、浏览器打印 PDF 与 PNG 长图导出。
